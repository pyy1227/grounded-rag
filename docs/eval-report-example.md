# RAG 评测报告（示例）

> 由 `ragagent eval --report reports/eval.md` 生成后整理。
> 数据为仓库自带评测集，**只用于配置对比，不代表线上效果**。

- 语料：15 篇文档 / 121 个 chunk（售后、物流、发票、会员、支付、优惠券、账户、维修、促销、3 个商品参数）
- 评测集：57 条，按 6:4 分层拆成 dev 34（23 可答 + 11 不可答）与 test 23（16 可答 + 7 不可答）
- 题面为**口语化改写**，不照抄知识库原词（如「是他们发错颜色了，寄回去的快递钱还要我掏吗」）
- 运行模式：BM25 + text-embedding-v3 + 短语召回 → RRF → heuristic 精排 → 语义拒答校验
- 分词：bigram

## 检索层

同一套检索参数，只换 embedding（test 未参与任何调参）：

| 指标 | dev · 哈希向量 | dev · 真实向量 | test · 真实向量 |
| --- | ---: | ---: | ---: |
| recall@3 | 0.6957 | **0.9130** | 0.9375 |
| recall@3（文档级） | 0.8696 | **0.9130** | 1.0000 |
| recall@5 | 0.8261 | **0.9130** | 1.0000 |
| MRR | 0.5667 | **0.7464** | 0.9115 |

哈希向量本质是字符 bigram 的袋，口语改写一上就掉；语义向量能靠 paraphrase 命中，dev 上差 20+ 个百分点。

两个口径并存的原因：`recall@k` 要求命中 gold 指定的章节，`recall@k_doc` 只要求命中 gold 所在文档。
同一答案在 15 篇语料里可能散落在两处（比如"货到付款"在《发货与物流》和《支付与结算》都写了），
文档级口径用来抵消这类标注歧义。

## 拒答层：为什么换掉了「数未见词」

先看词面信号在 dev（34 条）上的上限（balanced accuracy =（1 − 误拒 + 拒答准确）/ 2）：

| 拒答信号 | 最佳 balanced | 该点误拒率 | 该点拒答准确率 |
| --- | ---: | ---: | ---: |
| 未见实词比例（旧：全量 token 等权） | 0.70 | 0.61 | 1.00 |
| 未见实词比例（新：滤虚词 + bigram 0.5 权） | 0.74 | 0.52 | 1.00 |
| top-1 精排分数 | 0.57 | 0.85 | 1.00 |
| top-1 覆盖度 | 0.72 | 0.56 | 1.00 |
| 覆盖度 ∧ 未见比例（联合） | 0.63 | 0.15 | 0.40 |

结论：词面信号在这份口语化集上**分不开**可答与不可答——它们度量的是措辞，不是"资料里有没有答案"。

降噪本身有效，但只解决了一半问题：

| 指标 | 旧信号 | 新信号（滤虚词 + bigram 降权） |
| --- | ---: | ---: |
| 可答问题的比例（p50） | 0.67 | **0.21** |
| 可答问题的比例（max） | 1.00 | **0.58** |
| 两类是否可分 | 重叠 | **仍重叠** |

噪声降下去了（可答样本不再被虚词顶到 0.8 以上），但不可答样本一起降下来，间距没变。
同一个默认阈值 `max_unseen_ratio = 0.8` 下，新信号甚至一条都不触发（误拒 0、拒答准确 0）。

所以最终改成**语义校验**：把问题与前 3 个检索段落交给模型，问「仅凭这些资料能否回答」。

| 配置（dev） | 误拒率 | 拒答准确率 |
| --- | ---: | ---: |
| 纯词面（旧信号，阈值 0.8） | 0.26 | 0.27 |
| 纯词面（新信号，阈值 0.8） | 0.00 | 0.00 |
| **语义校验（`verify_mode = "llm"`）** | **0.0870** | **1.00** |

留出集（test，23 条，未参与调参）：误拒率 0.0000、拒答准确率 0.8571（6/7）。

## 两层校验：能不能答 vs 答得有没有依据

**第一层（回答前）**：三档判定 `answerable / need_more / cannot`。
分三档的目的不是更严，而是区分「资料里没有」和「这次没检索到」：
`need_more` 会触发一次扩大窗口的二次检索（`verify_retry_top_k`，默认 10），只有仍不满足才拒答。
本集上重试没有观测到救回案例（`need_more` 的样本重试后仍未变为 `answerable`），
所以它的价值目前是"把不确定显式化 + 留出重试通道"，收益要更大语料才看得出来。

**第二层（生成后）**：接地校验。检查答案的每条事实主张能否在引用段落中找到依据，
找不到就降级为摘录并标 `grounded=false`。压力测试（关掉第一层、强行生成）：

| 场景 | 结果 |
| --- | --- |
| 18 条不可答 | 12 条模型自己说"资料不足"（无引用→拒答）、1 条被接地拦下、5 条漏过 |
| 39 条可答 | 38 条正常、1 条被误伤（降级为摘录） |

漏过的 5 条都是"答了相关问题但不是所问"——接地校验查的是**主张是否有依据**，
不是"有没有回答问题"，后者由第一层负责（实测 11/11 全对）。两层是互补的，不能互相替代。

## 关于不可答样本的数量

一开始只有 5 条不可答，dev 上分到 3 条——**1 条题就是 33 个百分点**，"0.6 还是 1.0"可能只差一条，
这种数字不该拿出来讲。所以补到 18 条，覆盖四类"知识库完全没写"的问题：

| 类别 | 例子 |
| --- | --- |
| 商品属性未覆盖 | 耳机单只坏了能单独买一只吗 / 风扇的电池能自己换吗 |
| 政策未覆盖 | 能买延保服务吗 / 有生日双倍积分吗 / 支持学生优惠吗 |
| 凭证未覆盖 | 能开收据吗 / 能开捐赠发票吗 |
| 服务渠道未覆盖 | 能签企业采购合同吗 / 有以租代购服务吗 / 有线下维修网点吗 |

补完后语义校验在 dev 上 11/11、test 上 6/7（漏掉「会员可以转给别人吗」：检索到的是会员等级/优惠券，
不是「转让」政策，模型按「相关」判成了可答）；现在 1 条题 = 9 个百分点（dev）/ 14 个百分点（test），
仍然是演示级样本量，别当成线上指标。

## 局限

- dev 可答 23 条、test 可答 16 条：1 条题分别等于 4.3 / 6.3 个百分点，别抠小数点后两位；
- `MRR` 现在按请求的 top-k 截断后计算；修复前 `need_more` 扩窗会把第 6–10 名也算进来，
  有 Key 时建议重跑 dev 报告确认这一行；
- 语义校验多一次模型调用（约 +1s），评测里按 `(问题, 前 5 个 chunk)` 缓存；模型判定本身有噪声；
- 离线模式没有 Key，只能退回词面信号，此时拒答准确率为 0（误拒 0、拒答准确 0，等于从不拒答）；
- 语料仍是演示级（15 篇 / 121 chunk），检索指标比真实业务库乐观。

## 复现

```bash
cp .env.example .env          # 填入 DEEPSEEK_API_KEY / DASHSCOPE_API_KEY
ragagent ingest data/docs --force

# 调参用 dev；test 是留出集，只在最终报告里跑一次
ragagent eval --dataset data/eval/queries-dev.jsonl --report reports/eval-dev.md
ragagent eval --dataset data/eval/queries-test.jsonl --no-sweep --report reports/eval-test.md
```

没有 Key 时用离线配置（哈希向量 + 词面拒答）：

```bash
ragagent --config config.offline.toml ingest data/docs --force
ragagent --config config.offline.toml eval --dataset data/eval/queries-dev.jsonl --report reports/eval-dev-offline.md
```
